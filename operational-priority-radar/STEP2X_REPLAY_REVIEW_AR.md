# Step 2X — إعادة بناء E/B التاريخية للقراءة فقط

**تم تنفيذ مسار تجريبي حقيقي، لكنه ليس استرجاعًا إنتاجيًا كاملًا.**

- `recovery_signal_replay.py` يستهلك خطة REST المعتمدة من `recovery_chronology.py` ويعيد تقييم شموع Alpaca الأصلية عبر محرك Early Core المجمد ومحرك Base Ready الموجود، بترتيب اكتمال الشموع، دون تغيير العتبات.
- يخرج أول إشارة E وأول إشارة B **ضمن نافذة الاسترجاع المتاحة فقط**، مع زمن الحدث الأصلي ووقت الإتاحة الجديد عند الاسترجاع؛ لا يعيد تأريخ قرار الدخول إلى الماضي.
- `ProductionStartupRecovery(..., audit_window_signals=True)` يفعّل التدقيق اختياريًا على دفعات؛ **الافتراضي معطّل** لحين قياس زمن المعالجة على كامل الكون. لا توجد كتابة Redis أو Confluence أو إرسال Telegram في هذا المسار.
- يفشل عند تكرار حدث داخل الخطة أو فقدان إثبات native5 أو اختلاف زمن الاسترجاع أو تجاوز حد الأحداث.
- CI يفحص Redis 7 فعليًا ويشغّل اختبارات Lua الستة كخطوة إلزامية مستقلة، ثم يشغّل unittest و`pytest -q` ويحفظ المخرجات الأصلية.

## ما يمنع تفعيل LIVE_TRUSTED

1. نافذة REST ليست بالضرورة الجلسة كاملة؛ الإشارة الأولى فيها ليست إثباتًا لأول إشارة في الجلسة.
2. لا يزال مطلوبًا إعادة كتابة E/B الصحيحة إلى Redis بملكية وجيل القيادة الحاليين بعد إثبات تغطية التاريخ، وإعادة بناء حالات الصفقات القائمة والتوقف.
3. لم تُدمج رسائل SIP الملتقطة في نفس المسار بعد، ولم يُنفذ تسليم CAPTURING→DRAINING→DIRECT بعد التحقق من الاستمرارية.
4. اختبار Alpaca SIP 407 الحقيقي تحت حمل السوق مطلوب. لا نشر Render ولا دمج main قبل ذلك.

**التدقيق الاختياري لا يمنح ثقة للسوق، و`continuity_verified(epoch)` لا تزال False عمدًا.**
