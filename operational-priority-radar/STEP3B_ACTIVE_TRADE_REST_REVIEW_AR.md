# OPR Step 3B — سلامة استرجاع الصفقات النشطة عبر REST

**الهدف:** منع اعتماد نتيجة وقف/هدف عند استرجاع شريط صفقات ناقص أو شموع ناقصة بسبب الترقيم. هذا تعديل لمسار الاسترجاع الفعلي، وليس إثباتًا لتغطية SIP أو جاهزية Shadow.

- أضفنا `trades_audited` و`bars_audited` لكل رمز في `AlpacaREST`، مع 64 صفحة و100,000 صف كحد افتراضي لكل طلب. التكرار في `next_page_token`، الاستجابة المشوهة، فقدان مفتاح الصفوف، أو تجاوز الحد يفشل الاسترجاع صراحةً. واجهتا `trades` و`bars` القديمتان تستخدمان المسار المحدود نفسه.
- `ActiveTradeChronologicalReconciler._events` يشترط الآن نهاية سلسلة صفحات الصفقات والشموع **قبل** أي حدث تداول أو كتابة Redis؛ ويتحقق من طوابع زمنية واعية للمنطقة الزمنية، وصلاحية السعر/الإغلاق، وعدم وقوع الأحداث بعد نهاية نافذة الاسترجاع. الصف المعطوب لا يُتجاهل بصمت؛ فقد يخفي أول وقف.
- مصادر REST المحقونة في الاختبارات القديمة ما زالت مدعومة، لكن هذه التوافقية لا تمنحها شهادة ترقيم. الاسترجاع الإنتاجي عبر `AlpacaREST` يستخدم التدقيق الإلزامي.
- أضفنا 15 اختبارًا تشمل الصفحات المتعددة، التكرار، حدود الصفوف والصفحات، فقدان البيانات، عدم إجراء كتابة Redis عند الفشل، ورفض الصفقة غير الصالحة قبل اعتماد هدف زائف.

**حدود الإثبات:** نهاية صفحات REST ليست إثباتًا أن كل صفقات SIP وصلت إلى المزود، ولا تعيد حالات halt التاريخية، ولا تعطي ثقة لاستمرارية SIP بعد 407. `ProductionStartupRecovery.continuity_verified` لا تزال `False`. إذا تجاوزت صفقة نشطة 100,000 صف أو 64 صفحة، يفشل الاسترجاع بأمان بدل إعطاء نتيجة جزئية؛ يلزم تصميم تجزئة زمنية مثبتة قبل دعم هذه الحالات.

**لا دمج في main، ولا نشر Render، ولا تفعيل تنبيهات دخول.** نتائج `pytest -q` وRedis الحقيقية تصدر من GitHub Actions داخل الحزمة.
